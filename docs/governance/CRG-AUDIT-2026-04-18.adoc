=== Self-consistency paradox (HYP-S005 canary)

`STATE.a2ml` simultaneously declares:

- `version = "0.1.0"`,
- `completion-percentage = 100`,
- `phase = "CRG C Complete - Test Coverage Achieved"`,
- `crg-grade = "C"`.

And `ROADMAP.adoc` line 11 simultaneously declares:

- `== Current State: v0.0 (Alpha)` — a *lower* version than STATE admits.

And `README.adoc` line 46 simultaneously declares:

- `*Version 0.1* - Core functionality complete`.

And `README.adoc` line 41-44 *Current Status* table declares every
feature "✓ Working"; but `ROADMAP.adoc` lines 31-36 declare
`Shell_Manager.Detect_Shells` **"Stub only"** and
`Shell_Manager.Is_Modularized` **"Partial"** for the same build.

Four documents, four different stories. The v2.0 "honest D > dishonest B"
clause is violated before a single external check is applied. Per the
HYP-S005 detector: if completion = 100 is correct, the version cannot
be 0.1.0 / v0.0 (minimum bump to 0.5.0 for a "CRG C complete" claim,
1.0.0 for `completion-percentage = 100` with no caveats); if version
0.1.0 is correct, the completion figure is a lie. Since ROADMAP and
README both concede stubs in core modules, the *completion* figure is
the lie.

=== CATASTROPHIC FINDING 1: `Justfile` build/test/lint recipes are placeholder echoes

The Justfile's core RSR recipes *do not execute any work*:

[source,makefile]
----
# Build
build:
    @echo "TODO: Add build command"

# Test
test:
    @echo "TODO: Add test command"

# Clean
clean:
    @echo "TODO: Add clean command"

# Format
fmt:
    @echo "TODO: Add format command"

# Lint
lint:
    @echo "TODO: Add lint command"
----

`just build` prints a string; it does not invoke `gprbuild modshells.gpr`
or any Ada compiler. `just test` prints a string; it does not invoke
`deno task test` despite `deno.json` defining that task. `just clean`,
`just fmt`, `just lint` are the same. The Justfile *appears* to exist
(RSR R-020 passes the file-existence check) but carries no operational
content.

This fails the v2.0 D-floor "test matrix + scope documented" clause
interpreted behaviourally — there is no `just`-invocable path from a
green checkout to a test run. A new contributor following `just test`
sees "TODO" and has no route to the actual test suite.

Separately: the `crg-grade` recipe at lines 84-87 parses
`READINESS.md` — a file that **does not exist** in this repo. The
badge-generator recipe at lines 91-98 does the same. Both fall through
to the `X` (untested) default silently, so any external user
instrumenting against `just crg-grade` gets `X` regardless of actual
state. The self-declared `C` never surfaces through the tool's own API.

=== CATASTROPHIC FINDING 2: entire test suite is TypeScript (banned language)

STATE.a2ml `[test-coverage]` credits 66 tests across five suites. All of
them are written in *TypeScript*:

[cols="2,1,3"]
|===
| Suite | `Deno.test` count | File

| unit         | 15 | `tests/unit/shell_config_test.ts`
| property     | 11 | `tests/property/config_properties_test.ts`
| e2e          |  9 | `tests/e2e/shell_lifecycle_test.ts`
| aspect       | 31 | `tests/aspect/security_test.ts`
| bench        |  — | `tests/bench/config_bench.ts`
| *total*      | *66* | 5 `.ts` files (+ Ada test `test_shell_manager.adb` + `smoke_test.sh`)
|===

TypeScript is on the Hyperpolymath BANNED list with ReScript as the
mandated replacement (CLAUDE.md language policy). The repo's own
`rsr-antipattern.yml` workflow exists *specifically to block this*.

The violation was hidden by amending the anti-pattern check itself.
`.github/workflows/rsr-antipattern.yml` line 32:

[source,bash]
----
TS_FILES=$(find . \( -name "*.ts" -o -name "*.tsx" \) \
  | grep -v node_modules \
  | grep -v 'bindings/deno' \
  | grep -v '\.d\.ts$' \
  | grep -v '^./tests/' || true)       # <-- ADDED BY THIS REPO
----

The trailing `grep -v '^./tests/'` filter was *added in this repo* to
suppress the ban on its own tests. The monorepo-nested copy at
`verification-ecosystem/modshells/.github/workflows/rsr-antipattern.yml`
does *not* carry that exclusion — compare the two:

[source,diff]
----
< TS_FILES=$(... | grep -v '^./tests/' || true)   # modshells/
---
> TS_FILES=$(... || true)                          # verification-ecosystem/modshells/
----

Per v2.0 strict interpretation, tailoring the policy gate to hide a
violation fails the "honest D > dishonest B" clause harder than merely
missing the policy — it is *editing the speed camera to look the other
way*. Under the language-policy rule, every test file in the declared
`[test-coverage]` must be rewritten in ReScript (or another allowed
language) before the suite can be counted at all. Until that rewrite,
the 66-test claim supplies *zero* language-policy-compliant test
evidence.

This simultaneously violates:

. **Language policy** (CLAUDE.md): no TypeScript.
. **D-floor RSR compliance**: the antipattern workflow is gamed to pass.
. **C-grade "deep annotation"** clause: the gamed workflow is itself
  an undocumented, self-excepting rule carve-out — the opposite of
  "deep annotation".

== Verdict

*Current CRG grade: **E (Pre-alpha)**. Demote two grades from
self-declared C.*

Self-declared: *C*. Audited: *E*. This is the second two-grade demotion
in this session's Bucket-B sweep (matching neurophone's C→E). The
demotion rationale is *different in structure* from neurophone: neurophone
failed D-floor via committed merge conflicts; modshells failed D-floor
via a stub Justfile *and* a banned-language test suite *and* a gamed
antipattern workflow. Three independent D-floor breaks, not one.

Reasoning (one sentence): STATE.a2ml declares `completion-percentage = 100`
at `version = "0.1.0"` with 66 tests supporting a C claim, but the
version/completion pair is internally contradictory (HYP-S005 canary
tripped), the 66 tests are all in banned TypeScript, the language-policy
workflow was amended in-repo to hide that violation, and the Justfile's
core recipes are `echo "TODO"` stubs — so neither the D-floor "RSR
compliance mandatory" clause nor the C-grade "CI green + deep
annotation" clause is met before the per-directory-README question
even arises.

The E grade is earned, not conservative-by-default, on three positive
signals that keep it above X/F:

1. Real Ada code: `shell_validator.{ads,adb}` (~43 KB) and
   `shell_manager.{ads,adb}` (~22 KB) are non-trivial
   safety-critical-flavoured Ada — not vapourware.
2. Zero dangerous-pattern uses (`believe_me`, `assert_total`, `Admitted`,
   `sorry`, `unsafeCoerce`, `Obj.magic`, `unsafe_blocks`) in `src/`.
3. EXPLAINME.adoc is substantive, honest, and lines up claim-for-claim
   with the implementation — including explicit "Caveat" paragraphs.
   If the other annotation artefacts were of this quality the gap to C
   would be much narrower.

What blocks *immediate* promotion to D (do these first):

. **Un-game the language-policy workflow.** Revert the `grep -v '^./tests/'`
  line from `.github/workflows/rsr-antipattern.yml` line 32. This will
  make CI red. That redness is *correct*.
. **Rewrite the 66 `Deno.test` blocks in a policy-allowed language.**
  Options: (a) ReScript + Deno (consistent with the banned/allowed
  table), (b) Ada AUnit extending `test_shell_manager.adb`, (c) a
  Gleam suite calling into Ada via FFI. Pick one per-suite, not a mix.
  Delete the `.ts` files in the same commit as the new suite.
. **Replace Justfile TODO echoes with real commands.** `just build`
  must call `gprbuild -P modshells.gpr`. `just test` must run the Ada
  AUnit suite *and* the rewritten allowed-language suite. `just fmt`
  must call `gnatpp` or equivalent. `just lint` must call `gnatcheck`
  or equivalent. `just clean` must remove `obj/`, `bin/`, `.cache/`.
. **Reconcile version vs completion vs phase.** Either bump version to
